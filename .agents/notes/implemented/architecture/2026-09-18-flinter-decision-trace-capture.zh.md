# Agent Note：FLINTER DSH 决策轨迹捕获

状态：已实现

[English](2026-09-18-flinter-decision-trace-capture.md) | 中文

## 问题

FLINTER 在衡量轨迹能否改进诊断、以及以后构建经审阅的推理库之前，需要从当前 DSH 会话取得包含失败的决策证据。生产者专属载荷可能包含提示词、媒体、凭证、提供方文本或不稳定实现字段，而且轨迹记录失败不能改变被观察的工具决策。

## 决策

`@deepseek-ai/dsh-decision-trace` 是接入现有 ToolRuntime 扩展点的可选函数插件。生产者按准确工具名称注册两个同步投影器。插件验证其有界白名单输出，在执行前追加一个只写日志的 `flinter/decision-selection` 事件，并在最终结算后追加一个 `flinter/decision-result` 事件。投影、验证或追加失败只产生固定且有界的诊断码，绝不改变工具结果。

决策 ID 使用长度前缀编码持久会话 ID 和调用 ID，因此两个会话中的相同调用 ID 保持不同，也无需使用易碰撞的本地哈希。持久回放会验证两个投影、去除完全相同的重复阶段、拒绝发生变化的阶段内容或配对身份，并把缺少任一半的配对明确保留为 `incomplete`。

此软件包只保存不透明引用、计数、封闭状态和就绪标志。它排除原始参数、提示词、思维链、提供方内容、结果内容、凭证、网址、媒体字节和异常文本。它不改变策略，也不写入索引或推理库。

## 考虑过的替代方案

**在推理库插件中订阅。** 这会在轨迹价值尚未测量前，把未经证明的捕获字段耦合到下游学习格式。捕获保持独立；推理库适配器延后到评估基线存在之后。

**合并旧实验 DSH 轨迹分支。** 该分支包含无关的生产者和推理库假设，而且已经与当前 master 分叉。此软件包改用当前 ToolRuntime 与 Session 扩展点。

**持久化完整 ToolRuntime 输入和输出。** 原始值会扩大保留范围，并让脱敏依赖每个下游读取方。生产者改为在捕获位置发出明确且有界的投影。

## 后果

当前 DSH 可以记录并回放确定性的决策配对，而无需修改 agent loop 或模型可见数据。生产者适配器仍是独立工作；软件包夹具不能证明真实提供方、持久化重启、开销、审阅者或交付收据。推理库保持在此软件包之外，直到轨迹驱动评估明确其输入和晋升策略。
