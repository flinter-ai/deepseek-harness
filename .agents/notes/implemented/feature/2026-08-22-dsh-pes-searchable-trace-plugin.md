# Agent Note: dsh-pes searchable-trace plugin

Status: implemented

English | [中文](2026-08-22-dsh-pes-searchable-trace-plugin.zh.md)

## Problem

The searchable-trace producer slice ([flinter-ai/flinter-common `feat/searchable-trace-engine`](https://github.com/flinter-ai/flinter-common), immutable SHA `c05c3fc747f0aa0fcb9d0603009add71c59e091b`) delivered the engine — `event_index` + the `event_index.query` JSON-lines CLI with four bounded modes (search / similar / counterfactual / zoom) — but no agent-facing surface. The DSH side needs a sibling plugin that exposes those four modes as native tools while honoring the producer's boundary rules: the engine must be reached through an explicit configured command seam (never imported from a sibling checkout or a mutable branch at runtime), and the local engine's honesty semantics (provenance, abstention, bounded output) plus its failure surface (malformed input, timeout, nonzero exit, artifact references) must survive as structured tool results, not be swallowed.

## Decision

Ship `examples/dsh-pes` (`@flinter/dsh-pes`) on branch `feat/dsh-pes-plugin` (base `5c679222`, the merged dsh-segment S1 checkpoint `flinter/dsh-segment`), using the dsh-orca plugin's structural conventions (bundle patch + profile-discovery loader spec + keyless Loader smoke over the fixture stub):

- **Four registered tools, one shared bounded envelope.** `search_events`, `find_similar_states`, `find_counterfactuals`, `zoom` map 1:1 to engine modes. Result `n` is capped (`MAX_RESULT_N` = 50) and clamped to the corpus; state arrays (≤ 32 items), text fields (≤ 1024 chars), and engine stdout/stderr byte caps (8 MiB / 256 KiB) bound every request and response. Numeric/string-length bounds live in `query.js` semantic validation, not in schemas, because the tools JSON-schema subset has no such keywords (verified against `packages/core/tools/src/json-schema.ts`).
- **Explicit engine seam (`engine.js`).** The CLI is spawned as a subprocess with one JSON request line on stdin; the plugin never imports `event_index`, the sibling checkout, or a mutable branch. Command resolution: `config.command` → `$PES_QUERY_COMMAND` (JSON array) → packaged default `['python3', '-m', 'event_index.query']`; events index: `config.events` → `$PES_EVENTS_ENRICHED_JSONL`, always passed explicitly as `--events PATH`. `timeoutMs` is validated at load (1..120000); a deadline kills the child and settles `engine-timeout`.
- **Structured results preserve the engine's honesty and failure surface.** Every result is an envelope with `provenance` (plugin + engine protocol + optional `engine_pin`), per-event provenance passed through unchanged, `status: completed | abstained | error`, honest abstention from the engine mapped to `abstained`/`abstained` status (never an error), and a stable `error.kind` for `malformed-input`, `engine-timeout`, `engine-nonzero-exit`, `engine-malformed-response`, `engine-unavailable`, and `artifact-reference-missing`. Engine per-request `{"error": ...}` responses become `malformed-input` results; nonzero exits without a parseable response preserve `exit_code` + bounded `stderr`; a returned event whose `source_path` does not resolve under `config.artifactsRoot` fails the whole call loud (fail-closed).
- **Bundle/patch/config wiring per the existing conventions.** `cordis.patch.yml` inserts the `dsh-pes` row; `examples/package.json` links `@flinter/dsh-pes: link:./dsh-pes` (pnpm-lock.yaml updated, 3 lines); `tests/loader.spec.ts` drives the real `composeEntries`/`loadOverlayPatches` over the checked-in base + headless + pes patch files and asserts the row; `tests/contract.spec.ts` + `tests/keyless-smoke.e2e.ts` boot the real Loader from `tests/fixtures/pes.cordis.yml` via `@deepseek-ai/dsh-loader-smoke` with the seam filled by a protocol-compatible fixture stub (`stub-engine.mjs`, self-contained — it re-implements the documented contract for the fixture corpus and never imports the engine); `tests/seam.spec.ts` pins the seam and the whole taxonomy in-process (timeout, nonzero exit, ENOENT, three protocol violations, plug-in-side and engine-reported malformed inputs, both abstention paths, missing-artifact fail-closed, bounds, config/env precedence).
- **Integration gates documented, not completed.** Runtime engine packaging and the immutable producer pin are integration-gate work: the README records the producer SHA as provenance documentation and documents `config.engine_pin` (flows into every result's `provenance.engine_pin`); until packaging lands, an unimportable engine surfaces as a structured `engine-nonzero-exit`/`engine-unavailable` result, never a silent empty answer.

This PR changes nothing in `flinter/aws-runtime`, `DSH_COMMIT`, control-plane code, `~/.dsh` credentials/settings, or any AWS/cloud resource. It does not merge dsh-segment (or dsh-pes) into aws-runtime.

## Alternatives considered

**Import the engine package directly from the sibling worktree.** Rejected: the task boundary forbids importing a sibling checkout or mutable branch at runtime, and a hard import would couple this repo's plugin to an unpinned path that does not exist for other consumers (CI, workers). The subprocess seam keeps the boundary at an explicit configured command.

**Validate bounds through JSON-schema keywords (`minimum`, `minLength`, `maxItems`).** Rejected after checking `packages/core/tools/src/json-schema.ts`: the enforced subset supports only type/oneOf/properties/required/additionalProperties/items/enum/const + annotations, so numeric/length constraints would fail at Loader boot. Semantic validation sits in `query.js` before any spawn (fail-loud structured `malformed-input`, not silent clamping).

**Return engine failures as thrown errors / `isError` results.** Rejected: the task requires failures to be preserved as *structured tool results*; the design maps every engine failure into the envelope's `error` block with a stable `kind` (the tools registry still owns `isError` for schema violations and unknown tool names).

## Consequences

The plugin registers exactly four tools; `tests/loader.spec.ts`, `tests/seam.spec.ts`, `tests/contract.spec.ts`, and `tests/keyless-smoke.e2e.ts` pass in both src (tsx) and built-`lib/` modes. `engine_pin` is absent (not `null`) in provenance until a deployment pins the engine — explicit "not pinned" provenance, matching the integration-gate scope. The fixture events corpus (schema-exact PhysicalEvent JSONL derived from the producer's loader at authoring time, with `source_path` artifact refs) and the two scan artifacts under `tests/fixtures/artifacts/` are committed test data only. The next step is the integration gate: package the engine so `config.command`'s default resolves, pin the producer SHA, and validate against real indexes/labels — all explicitly NOT_RUN here. The dsh-segment S1 note is untouched; this note documents the sibling searchable-trace surface.
