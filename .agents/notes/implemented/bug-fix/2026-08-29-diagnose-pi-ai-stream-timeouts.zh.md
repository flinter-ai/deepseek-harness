# Agent Note: 诊断 pi-ai 流超时阶段

Status: implemented

English | [English](2026-08-29-diagnose-pi-ai-stream-timeouts.md)

## Problem

pi-ai 适配器对所有空闲超时使用相同消息，但提供方可能在产生任何已转换分片之前停顿，也可能在部分响应之后停顿。持久化重试层因此无法在调查失败请求时区分这两种情况。

## Decision

pi-ai 适配器为每个请求统计已转换的流事件。`TIMEOUT` 失败现在记录提供方路由、模型，以及空闲期发生在第一个已转换事件之前还是已统计的部分响应之后。适配器仍通过现有 watchdog 中止提供方流，并继续使用相同的稳定 `TIMEOUT` 失败代码。

实时 ARK profile 从普通可重试代码中移除了 `TIMEOUT`。因此，可能已经被提供方接受的请求在五分钟空闲后不会被自动重放；限流、服务端、传输和空响应恢复保持不变。

## Alternatives considered

**增加空闲超时时间。** 否决：这会让无进展的请求占用 agent 更久，也不能区分提供方停顿和正在缓慢产生响应。

**重试所有超时。** 对 ARK 路由否决：空闲超时不能证明提供方拒绝了请求，盲目重放可能重复工作并产生重复计费。现有按提供方配置的可重试代码列表保留了路由级决策。

**修改全局重试策略。** 否决：其他提供方和直接传输部署可能具有安全的超时重试语义，因此其行为必须继续可配置。

## Consequences

下一次超时日志会在不暴露凭据或提示内容的情况下标识请求阶段。ARK 超时现在需要用户发起重试或其他下游恢复操作。适配器没有增加提供方健康检查或自动故障转移；这些功能需要明确的路由策略，并可能改变模型可见行为。
